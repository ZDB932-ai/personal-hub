# 本地账户与恢复密钥

账户仅标识当前设备的保险库，不是云端账号，不提供多账户切换或邮箱重置。

## 使用流程

- 空设备：填写账户名称与至少 8 位密码，保存恢复密钥文件或手动记录，填写末 8 位并确认完整密钥已另存后创建账户。新账户直接使用 v3 随机数据密钥。
- 已有设备：原密码仍可登录。在「设置 → 安全 → 本地账户与恢复」验证当前密码，设置名称并生成恢复密钥。v2 需要先迁移到 v3；迁移前导出备份，所有附件须在本机，旧版整库同步将停用。
- 忘记密码：选择「忘记密码？」，填写恢复密钥及新密码。成功后返回登录页，旧密码不再打开当前封装。恢复不自动登录。
- 重新生成：先保存新密钥，再确认启用；提交成功后旧密钥对当前设备的当前恢复记录失效。普通改密不会使恢复密钥失效。
- 没有预设恢复密钥的设备不能恢复已遗失密码的数据。清除数据是单独折叠的双重确认危险操作。

## 存储和边界

账户名称和恢复封装保存在 Repository 的 xk.lock.v2，与密码封装通过同一事务提交；名称会在锁屏显示。恢复密钥为 256 位系统随机数，显示为 8 组十六进制，可忽略空白、连字符和大小写。明文密钥不写入应用存储；用户可通过原生保存流程导出独立文本文件。

恢复封装使用 AES-256-GCM，附加认证数据绑定独立用途域、版本、vaultId/keyId。恢复先验证数据密钥能解密当前信封，再使用新密码封装原数据密钥。业务密文、附件、连接凭据和业务时间戳不改变。写入失败不覆盖旧封装。恢复后关闭本机指纹凭据，需重新启用。

恢复信息仅限当前设备，不随逐条同步、普通 .phub 备份或 .phub-device 转移；其他设备加入后需单独设置。恢复密钥不能代替数据备份，不能找回已删除的数据库或附件。重新生成不撤销历史副本中的旧恢复封装，也不进行数据密钥轮换。

旧账户升级和恢复配置分为两次事务：如果升级完成但恢复信息保存失败，数据仍为 v3，原密码继续可用，需重试配置。

## 验证

npm run build：类型检查及生产构建。

npm run test：全部单元测试；新增创建、错误恢复、绑定与篡改、旧库升级、轮换、改密后恢复、写入失败、附件和连接凭据保留验证。

node scripts/verify-local-account.mjs：隔离 Edge 验证创建、确认、刷新、错误恢复、重设、旧密码拒绝、任务保留、轮换和 320/390/768/1440 登录布局。

node scripts/verify-ui-redesign.mjs：按新账户流程创建后运行既有页面回归。
