## 实现与验证记录

入口为「今天 → 桌面 Todo」或「设置 → 桌面」。打开小窗后，可以选择今天、指定任务或指定标签；「锁定可见」独立勾选。指定任务支持拖动排序和上下移动。小窗支持快速添加、完成确认、子任务勾选、置顶、折叠、缩放、边缘吸附，以及托盘显示、关闭和找回位置。

关闭主窗口会隐藏到托盘，桌面清单继续显示并使用同一任务库。窗口间修改即时传递；已有云同步连接在小窗可见时继续周期拉取，锁定后暂停。小窗提交操作等待本机加密存储回执，失败可重试；重复请求不会重复生成任务。退出会先保存已经接收的操作。

锁定后仅保留指定任务的标题、日期、时间和完成状态，显示快照时间，所有编辑入口移除。快照仅在内存中，重新启动必须解锁才可恢复任务。展示授权使用 `xk.desktop-todo.secure` 加密保存，改密时迁移，备份替换时撤销；位置、大小、置顶等普通偏好独立保存为 `desktop-todo.json`。

## 1. 目标与已确认选择

将现有每日任务增加为一个可独立展示的 Windows 桌面清单。用户关闭主窗口后，仍可在桌面查看、添加和完成待办；小窗可拖动、调整大小、折叠、选择置顶，并与主页面共用任务数据。

用户已明确选择：**应用锁定后，保留指定任务的只读展示。**

建议采用以下产品定义：

- 「关闭主窗口」：隐藏主窗口，程序留在托盘，桌面 Todo 继续运行。
- 「关闭桌面 Todo」：关闭小窗并取消自动展示，任务保留；可从托盘或今天页面重新打开。
- 「退出 Personal Hub」：完成待保存操作后退出进程，主窗口、小窗和桌宠一起关闭。
- 「应用锁定」：清除正常业务会话与密钥，仅保留明确允许展示的最小只读快照。
- 重启软件后仍须正常解锁；解锁后恢复小窗。只读快照不落盘，冷启动不能显示上次任务标题。

首版面向 Windows Tauri 桌面端。Web/Android 沿用现有任务功能，桌面窗口控制不在这些平台出现。Android 系统悬浮窗、Windows 桌面底层嵌入、进程完全退出后的显示均不纳入本期。

## 3. 入口与使用流程

### 第一次使用

1. 今天页面的次要操作增加「桌面 Todo」。打开配置面板，左侧选择清单，右侧预览。
2. 清单来源默认「今天」，同时折叠展示逾期组；可改为「指定任务」或「指定标签」。
3. 选定窗口外观和是否置顶；默认启用「主窗口关闭后继续展示」。
4. 在「锁定后展示」中逐项勾选任务，默认没有任何任务获得此权限。提供已授权数量和实际预览。
5. 点击「开启桌面 Todo」，出现小窗，配置持久化成功后才显示开启成功。
6. 主窗口关闭后，小窗保留；首次仅提示一次「已在托盘运行」。

### 后续入口

| 入口 | 操作 |
| --- | --- |
| 今天页面 | 显示/关闭桌面 Todo、选择展示内容 |
| 任务更多菜单 | 加入/移出指定清单；另设「锁定后允许展示」 |
| 设置 → 桌面 | Todo 偏好；现有桌宠入口继续独立保留 |
| 系统托盘 | 打开主窗口、显示/关闭 Todo、找回 Todo 位置、锁定应用、退出 |
| 小窗标题栏 | 拖动、置顶、折叠/展开、更多、关闭小窗 |
| 小窗任务标题 | 打开主窗口并定位到该任务 |

任务内容设置在解锁后修改；锁定时仍可拖动、折叠、隐藏、找回位置、关闭小窗。

## 4. 小窗布局与交互

### 标准清单

建议初始尺寸 360 × 480 DIP，最小 300 × 240 DIP；最大尺寸受当前显示器工作区限制。首版可调窗口大小，超长清单只在列表区域滚动，标题栏和底部输入固定。

```text
┌──────────────────────────────────┐
│ ⠿ 桌面 Todo       置顶 折叠 更多 × │
│ 今天 ▾                  2 / 5 完成 │
│ ──────────────────────────────── │
│ 今日重点                         │
│ □ 整理实验结果                   │
│   14:30 · 高优先级 · 子任务 1/3   │
│ □ 完成项目周报                   │
│   17:00 · 中优先级               │
│                                  │
│ ▸ 逾期 2 项       ▸ 已完成 2 项   │
│                                  │
│ + 添加待办…                 添加 │
│ 已保存到本机               打开主窗│
└──────────────────────────────────┘
```

以上为结构示意；产品图标使用 Lucide。

### 窗口行为

- 仅标题栏空白区域启动系统原生拖动；按钮、输入框、任务行不会误拖整个窗口。
- 原生边缘调整大小；标题栏更多菜单也提供「标准大小」「找回位置」。
- 可选边缘吸附：拖动结束后，距当前工作区边缘 12 DIP 内才轻吸附；不做持续追踪或自动巡游。
- 置顶默认关闭，用户可开启并记住选择。程序自动恢复小窗不抢焦点；主动点击输入时才获得键盘焦点。
- 折叠为一条约 56 DIP 高的摘要栏，展示待办数与展开按钮；锁定时数量只统计获准快照。
- 窗口位置和展开尺寸按显示器保存；跨屏时转换物理像素/DIP，副屏拔掉或屏幕分辨率变化时自动移回有效工作区。
- 靠屏幕边缘打开菜单时自动向内展开。任务栏区域不参与可放置工作区。
- 不做自动鼠标穿透，避免出现看得到却无法点击和拖动的窗口。
- 普通浮窗与系统「显示桌面」、独占全屏、虚拟桌面的组合行为须原生验证；不承诺首版将窗口嵌入 Explorer 桌面层。

### 清单选择与排序

| 来源 | 规则 |
| --- | --- |
| 今天（默认） | 当天任务，重点组在前，其余按优先级和时间排列；逾期单独折叠，不自动顺延日期 |
| 指定任务 | 用户手选 Task ID；可拖动排序，并提供键盘可用的上移/下移菜单；顺序仅作用于本机小窗 |
| 指定标签 | 展示选定标签下未完成任务，日期、重点、优先级信息保持可见 |

动态来源下不提供与自动排序冲突的拖排。已完成项移入折叠区，保留查看和重新打开入口。日期为空的任务不混入「今天」，仍可通过指定任务或标签展示。跨午夜自动重新计算今天与逾期，不修改任务本身。

「锁定后展示」始终是独立的明确 Task ID 白名单；切换清单、换标签、重复任务产生新记录都不能自动扩大白名单。首版重复任务的新实例需单独授权。

### 任务操作

- 快速添加：复用现有快捷解析，在当前清单上下文中提供明确日期/标签预览；指定任务清单创建成功后自动加入。解析不明确时保留文字，不能静默改日期。
- 勾选完成：小窗内展示紧凑确认，复用现有完成流程；可在更多操作中打开完整进展记录。完成普通任务、生成重复任务的下一次、子任务状态保持现有语义。
- 子任务：可按需展开并勾选，锁定后不展示子任务正文。
- 编辑标题、时间和复杂内容：点击标题或「编辑」回到现有主窗口任务表单，避免在窄窗塞入整套编辑器。
- 删除只在现有详情流程中进行；「移出桌面」不删除任务。
- 保存完成前显示待保存状态；失败时保留待处理操作与重试入口。窗口不能用一条“完成”提示掩盖未落盘。
- 撤销/重新打开沿用可定义、可验证的业务语义；对已经产生后续实例的重复任务，不以盲目反向 toggle 假装完全撤销。

### 视觉与无障碍

沿用 `design-system/MASTER.md` 和 `src/style.css` 的 surface、line、primary、t1–t4、ok、warn、danger 等语义 Token，跟随现有明暗和色调；首版采用实色可读底板，无额外渐变、毛玻璃或整窗透明。

标准卡片 12px、控件 8px，正文 14px、元数据 12px；紧凑布局通过减少次要信息实现，不压缩到不可点击。主要操作有可见焦点，触控目标至少 44px，长标题最多两行并提供完整查看。小窗内 Esc 先关闭菜单/确认框，不意外退出软件。减少动态效果模式下移除过渡。

## 5. 锁定后只读展示

这是本轮用户已经确定的行为，实施时无需重复询问。

### 保留范围

- 只保留锁定前已明确授权任务的标题、日期、时间、完成状态和快照时间。
- 不保留备注、子任务正文、标签内容、关联资料、账号信息、主密钥、连接令牌或完整任务对象。
- 快照只在进程内存中保留，不写入本地 JSON、localStorage、日志或普通备份。
- 本机加密配置保存 Task ID 白名单；重启后仍需解锁，才能重新生成展示快照。

### 锁定过程

1. 立即撤销可写会话，两个窗口都停止接受任务写入；小窗先显示「正在锁定」。
2. 排空已经被接受的保存操作，等候本地持久化回执。
3. 从最后成功保存的数据中生成最小白名单快照，将其交给 Rust 管理的内存状态。
4. 清除小窗的完整任务投影、输入草稿和待编辑内容，清除正常业务会话中的密钥与数据。
5. 小窗显示「已锁定 · 只读 · 更新于 HH:mm」，仅显示快照；没有授权任务则显示「解锁后查看待办」。

锁定时保存失败：保持隐私遮挡与写入暂停，显示「保存失败，锁定尚未完成」，提供重试/回主窗处理，不谎报已锁定。生成最小快照失败时优先隐藏任务内容，不能用旧的完整投影代替。

### 只读状态可做什么

可以拖动、缩放、折叠、关闭，或者选择「解锁以编辑」唤起主窗口。不能新增、勾选、改日期、查看未授权任务，也不能扩大展示范围。勾选控件在只读态替换为纯展示符号，不只做视觉禁用。

锁定后展示的是**锁定时快照**：不会保留解密能力来接收其他设备的新任务内容，也不标记为实时同步。解锁成功后丢弃快照并刷新。退出、账户切换、清空本机数据和保险库替换均清除快照。Windows 系统锁屏/恢复另测，系统恢复不能隐式解锁应用。

## 6. 窗口生命周期

| 事件 | 主窗口 | 桌面 Todo | 数据行为 |
| --- | --- | --- | --- |
| 首次开启 Todo | 可见 | 展开，可交互 | 订阅同一数据会话 |
| 点击主窗口 × | 隐藏到托盘 | 保持用户当前状态 | 解锁期间仍可编辑和同步 |
| 点击 Todo × / Alt+F4 | 不变 | 关闭并取消自动展示 | 保存已接受操作；任务保留 |
| 托盘「显示 Todo」 | 不主动弹出 | 按权限显示清单/只读快照/解锁提示 | 不隐式解锁 |
| 自动或手动锁定 | 锁定页，可保持隐藏 | 获准快照只读 | 停止业务解密与修改 |
| 解锁成功 | 正常工作区 | 重新获取最新投影 | 恢复编辑、提醒和已有同步 |
| 从托盘退出 | 退出 | 退出 | 先 flush；失败停留并提示 |
| 新进程启动 | 正常登录流程 | 初始不泄露任务 | 解锁后按偏好恢复 |
| 主 WebView 意外重载/失联 | 待恢复 | 清空可写投影，显示重连/解锁状态 | 不自行创建第二写入者 |
| 小窗意外重载 | 不变 | 先空白安全状态，再请求快照 | 不从浏览器持久缓存复活任务 |

「退出」需要从当前直接 `app.exit(0)` 改为统一退出协调：拒绝新操作 → 主会话 flush → 确认完成 → 清理快照和窗口 → 退出。失败时保留进程并提供重试；系统强制结束进程不承诺保存尚未提交的数据。

## 7. 技术架构

### 单一数据写入者

```text
主窗口/后台业务会话
  现有 tasks + database + 加密密钥 + 同步调度
             ↑ 任务命令 / ↓ 最小展示投影与保存回执
        Rust DesktopTodoState
   来源校验 / 会话状态 / 请求去重 / 窗口与位置
             ↑ 用户动作 / ↓ 定向事件或命令结果
       todo 独立轻量 WebView
  展示、输入与窗口交互；不初始化业务 Repository
```

初版复用关闭后仍存活的 `main` WebView 作为业务所有者，避免重写整个加密体系。小窗入口在 `src/main.ts` 中先分流，再进行普通 `initializeVaultRepository()`，与当前桌宠入口分流同类，但使用独立模块。

只对任务展示投影和操作传递消息；不发送保险库完整 payload 或 CryptoKey。小窗不启动云同步、通知扫描、数据库保存 watcher，也不导入会初始化全部 store 的模块。

### 消息与一致性协议

- 每个解锁会话有新的 `sessionEpoch`；每次内容投影递增 `viewRevision`。
- 请求包含 `requestId`、会话代号、任务 ID、显式目标状态、预期版本及最小参数；版本使用会话内递增序号，不能只把毫秒 `updatedAt` 当成严格锁。
- 完成操作使用 `setDone(true/false)` 语义，不能跨窗口发送无条件 `toggle`。子任务同理。
- 服务端 Rust 命令从注入的调用窗口获取真实 label，不信任前端自报来源。主窗口发布投影、状态、回执，小窗只能提交白名单任务动作与自身布局操作。
- 业务所有者串行处理请求、校验锁状态/任务存在/业务忙碌/版本，再调用共享任务服务；保存成功才回 `applied` 和新 revision。
- 同一 requestId 重试返回既有结果，不再次添加任务或生成重复实例。超时先查询结果/重取投影，不用新的 ID 盲目重发。
- 请求结果区分 `pending`、`applied`、`conflict`、`locked`、`failed`；小窗展示中与已落盘状态分开。
- 保存失败后保持受影响命令的待处理状态，后续同对象写入按序暂停；禁止整库盲目回滚覆盖其他修改。
- 任务被其他窗口删除/修改时返回冲突与最新状态，交给用户重试，不静默覆盖。
- 订阅建立后请求初始快照；重载后再握手。事件有 revision，旧会话及乱序消息丢弃，发生缺口请求完整投影。
- 租约/心跳检测业务所有者存活（建议 5 秒间隔、15 秒失联阈值，原生计时）；失联时清除可写展示，只有由锁定流程明确生成的白名单快照可以继续只读。
- 原生层在锁定、失联和退出时立即关闭命令通道；只靠按钮 `disabled` 不构成只读。

Tauri 事件没有按业务事件名隔离数据的 capability 机制，且应用自定义命令默认对所有窗口开放。实施必须配置自定义 command permissions / `AppManifest::commands`，并在 Rust 内再校验窗口来源。业务写入不直接信任任意前端 emit 的事件。参见 [Tauri 前后端事件说明](https://v2.tauri.app/develop/calling-frontend/) 与 [Capabilities](https://v2.tauri.app/security/capabilities/)。这些限制约束 IPC；不能把它描述成同源 WebView 之间完整的浏览器存储隔离。

### 小窗状态保存

| 内容 | 保存位置 | 说明 |
| --- | --- | --- |
| 开关、置顶、尺寸、位置、折叠、显示器信息 | 本机 `desktop-todo.json` 或集中窗口偏好 | 不含任务文字、标签、任务 ID；Rust 原子替换与字段 patch 合并 |
| 清单来源、标签选择、Task ID、手动顺序、锁定展示白名单 | 新增 Repository 密文键 `xk.desktop-todo.secure` | 使用当前数据密钥加密，仅业务所有者通过 `commitRepository` 保存 |
| 解锁时任务投影 | 内存 | 主 store 派生，按 revision 发布 |
| 锁定时只读快照 | Rust/小窗内存 | 最小字段，重启即消失 |

新增密文配置键必须同时纳入 Repository key 列表、v2 改密重加密、v2→v3 升级、账户切换/恢复/重置清理。v3 只改密码封装时数据密钥不变。配置不随云同步或设备加入转移；普通备份只包含既有业务任务，恢复时清除桌面授权并重新选择。旧版本无该键按关闭状态处理。

### 同步、活动与提醒

- 本机主页面↔小窗：按变更推送，目标稳定负载下交互反馈 ≤100 ms、成功落盘后的对端更新 P95 ≤500 ms；这是待验收指标。
- 云端：继续现有逐条同步与退避，仅在「主窗口可见或小窗可见」且解锁、联网时拉取；现有周期约 45–60 秒。任务写入继续触发当前同步调度，不新增第二个客户端。
- 跨设备不承诺毫秒实时。界面区分「已保存到本机」「待同步」「同步失败」；未配置云同步时只显示本机状态。
- 小窗真实键盘、点击、拖动计入现有自动锁定活动，并做节流；鼠标悬停、程序动画、同步事件、心跳不延长解锁时间。
- 跨午夜、系统时间变更、睡眠恢复后重算日期与相对时间，再请求新投影。相对时间最多按分钟更新，不做持续逐帧轮询。
- 通知继续由唯一提醒服务触发，保留 `lastRemindedTs` 防重复。关闭主窗口仍运行期间需实测提醒调度；应用锁定后保持现有暂停语义，只读快照不新建提醒。
- WebView 隐藏后的计时/调度必须用 Windows 实测确认。若受到限频，使用 Rust 原生定时唤醒主会话，不以关闭自动锁定或创建双份提醒器解决。

## 9. 实施顺序

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| A：窗口骨架与生命周期 | Todo 窗口、托盘、拖动/缩放/折叠/置顶、布局保存、退出协调 | 关闭主窗可用；关小窗/退出行为明确；多屏位置有效 |
| B：同一任务数据 | 投影协议、单一写入者、快速添加/完成/子任务、主窗详情跳转 | 双向更新且落盘回执正确；重复请求不重复执行 |
| C：清单与锁定 | 今天/手选/标签、加密偏好、白名单快照、自动锁定活动聚合 | 只读不能写；未授权内容不出现；改密和恢复兼容 |
| D：同步与原生验收 | 小窗可见时同步、跨日/睡眠、提醒、故障恢复、性能 | 自动化通过并完成 Windows 真机验收 |

A–D 共同构成首版完成标准；不能仅交付一个能拖动的展示框就称为全部完成。

后续可选增强：全局唤出快捷键（可配置并检测冲突）、开机启动（用户主动开启，启动仍锁定）、多个独立清单窗、专注窄条、窗口背景透明度。首版先交付一个可靠的完整清单窗和折叠栏，避免多窗口把并发和权限范围扩大。

## 10. 验收清单

### 核心场景

- [ ] 添加任务、开启小窗、关闭主窗口，任务保持可见且可勾选；从托盘返回主窗口，结果一致。
- [ ] 主窗编辑/删除任务时，小窗及时更新；小窗保存中主窗有其他编辑，不发生整库覆盖。
- [ ] 连点、事件重复、回执丢失、超时重试不会重复新增或重复生成周期任务。
- [ ] 指定任务拖排仅影响小窗；动态清单排序清楚；跨日、空日期、已完成和逾期规则正确。
- [ ] 只给部分任务锁定展示权限；自动锁定后仅出现这些任务的最小快照，UI 和 IPC 均不能写。
- [ ] 锁定前保存失败不能显示已锁定成功；不泄露未获准标题；恢复后不重放旧会话命令。
- [ ] 重启软件未解锁前没有上次标题；解锁后恢复清单；切换账户、导入保险库、清空数据后没有残留。
- [ ] 小窗正在操作时正常重置空闲时间；悬停和后台同步不能阻止自动锁定。
- [ ] 云连接正常时关闭主窗、只留小窗，其他设备变化可被拉取；锁定后清楚显示冻结快照。
- [ ] 未配置同步/断网时本机可用；失败不谎报成功；联网恢复沿用现有重试。

### Windows 原生场景

- [ ] 100% / 125% / 150% / 200% 缩放，主副屏混合 DPI 和负坐标显示器，拖动后不漂移。
- [ ] 拔掉副屏、改变分辨率、任务栏不同位置、菜单靠边、窗口曾移出屏幕时均可找回。
- [ ] 置顶开关、折叠、调整大小、主窗最小化/关闭、Todo Alt+F4、托盘退出行为符合状态表。
- [ ] 自动显示不抢焦点；输入/勾选不误触拖动；键盘可操作，长中文标题不挤压按钮。
- [ ] Windows 系统锁屏/解锁、睡眠恢复、主 WebView 重载、小窗重载均有明确安全状态。
- [ ] 与现有桌宠同时开启，托盘和窗口设置互不覆盖；程序单实例入口仍可恢复主窗口。
- [ ] 主窗隐藏后提醒只发一次，锁定暂停符合现有行为；不把通知 IPC 提交当作点击跳转已验收。
- [ ] 空闲小窗不加载 3D、PDF、AI 等业务包；对比开启前后 CPU/内存，报告实测值，不虚构资源指标。

### 工程验证

实施完成后在 Node 24 下执行 `npm run build`、`npm run test -- --maxWorkers=2`，并针对新协议/锁定/持久化运行有意义的测试；Rust 运行 `cargo test`，必要时 `cargo check`。补充独立 QA 配置和合成保险库进行 Windows 验收，避免接触正式账户数据。浏览器 mock 的拖动、跨屏和锁定结果不能替代 Windows 原生证据。
