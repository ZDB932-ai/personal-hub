# 界面风格

在「设置 → 外观 → 界面风格」选择面板设计。共十四款：经典纸感、晨光工作室、极光浮岛、精密面板、瑞士编辑、赛博终端、新粗野主义、复古桌面、自然手札、轨道空间、纸上工坊、工程蓝图、艺廊留白、像素游乐场。按简约专注、自然纸感、科技工作台、复古趣味和编辑艺术分类。

点击缩略图立即应用面板的排版、导航与卡片样式，保留现有明暗、色调和壁纸。「应用推荐配色」同时选用该款推荐的明暗模式与色调，仍保留壁纸；也可以在「颜色与显示」分别调整。全部风格支持浅色、深色与跟随系统，以及九种强调色。

「撤销更改」恢复上一次风格或推荐配色操作之前的外观，关闭设置、切换分区后仍可使用；刷新应用会结束这次撤销记录。外观偏好保存在本机 `xk.theme.v1`，不修改业务数据。原有用户继续使用原风格，未知风格值回退经典纸感。

## 设计与维护

前六款提取用户参考中的编辑排版、终端、粗野主义、桌面窗口、自然手札与未来空间语言；后四款分别延伸为工坊笔记、工程图纸、艺廊与像素风格。仅复用视觉语言，项目中的任务、日历、资料库和密码库继续使用原有交互。

- `src/lib/interfaceStyles.ts`：风格目录、文案、推荐色与模式。
- `src/interface-gallery.css`：新增风格的语义颜色、排版、导航、面板与预览；不依赖外部字体或图片。
- `src/stores/theme.ts`：持久化、系统明暗跟随、会话撤销快照。
- `src/components/settings/InterfaceStylePicker.vue`：选择、分类筛选、推荐配色和撤销。
- `index.html`：与目录同步的首屏风格白名单。
- `design-system/MASTER.md`：各款设计例外与约束。

壁纸开启时隐藏风格背景图案，透明信息框只改变面板背景，文字不跟随透明。装饰限定主工作区，避免影响桌面宠物透明窗口。导航继续支持折叠；大屏允许改变位置与宽度，小屏保留便于操作的导航顺序。

## 验证

使用 Node.js 24：

```powershell
npm run build
node scripts/verify-interface-styles.mjs
```

浏览器脚本从生产构建启动临时回环服务，创建隔离的合成账户，检查十四款明暗、五个主要页面、五种视口宽度、导航位置及遮挡、键盘切换、刷新持久化、透明面板、推荐配色与撤销，并执行任务操作链。结束后关闭浏览器与服务。

五种宽度的页面矩阵保存在 `.visual-qa/interface-personalities/`，包含 700 个页面组合、28 个设置页组合、28 次刷新持久化与 14 条导航操作链；该阶段发现的问题保留在原始报告中。修复后的补测与十款真实页面总览位于 `.visual-qa/interface-personalities-verified/`，覆盖 56 个表单组合、40 个日历视口组合、3 条完整任务操作链及十四款切换后的数据保留，报告为零失败。上一次较接近的布局保留在 `.visual-qa/interface-gallery/`，`before-after.html` 提供前后对照。彩色和灰度总览用于检查不同风格的轮廓差异，不能用配色差异代替布局验收。

局部修复可设置 `QA_CAPTURE_ONLY=1`、`QA_FINAL_PASS=1` 执行补测，或设置 `QA_FORMS_ONLY=1` 仅检查十四款表单在明暗和桌面/手机下的几何、44px 控件、文字对比度，以及关闭图标正常、悬停和移开后的对比度；用 `QA_OUTPUT` 指定独立结果目录，保留原始失败记录。

最后一次表单补测位于 `.visual-qa/interface-forms-verified/`：56 个表单组合和 168 个关闭图标状态全部通过，浏览器页面错误和资源请求失败均为零。终端浅色按钮与终端/粗野主义标题栏关闭图标的对比度已修正。

复古风格的最终设置截图位于 `.visual-qa/interface-retro-preview-verified/`。截图前等待有限动画完成，避免过渡期间的预览空白；针对性复核通过，原始采样异常保留用于诊断。

### 本机云登录预览

构建后可执行 `npm run preview:cloud`，访问 `http://localhost/`。当前云服务允许该来源，而 `http://127.0.0.1:4173` 会被来源检查拒绝，表现为「无法连接云服务」。浏览器以主机名和端口区分来源，地址不能互换；这个错误不代表密码错误。预览只监听回环地址，不修改云端来源配置。

## 设置与导航整理（2026-10-23）

设置采用分组目录和搜索。桌面同时显示目录与内容；手机先显示分类，进入分区后可返回分类。搜索“背景图片”会直接打开对应的外观子页。切换分区保留当前窗口内未提交的表单，关闭设置清理敏感输入；密码、备份与同步操作仍使用各自原有验证和保存流程。

| 设置分组 | 内容 |
| --- | --- |
| 个性化 | 外观、桌面伙伴、桌面清单（Windows） |
| 账户与数据 | 账户与恢复、隐私与锁定、同步与离线、备份与迁移 |
| 帮助 | 关于与帮助 |

外观包含颜色与显示、界面风格、背景图片和推荐搭配。十四款设计延伸到整个设置窗口，包括目录、标题、卡片、表单、下拉选项和状态说明。手动服务器配置、设备迁移及诊断收在可展开区域内，日常使用先看到当前状态和主要操作。

应用导航复用一份目录：日程与行动、知识与资料、账号与安全、AI 与扩展。桌面侧栏、不同风格的顶栏或底栏、手机“更多”使用相同名称与路由；AI 与扩展默认折叠。任务与计划、长期目标、项目收藏、桌面清单等入口名称保持一致，创建操作使用具体动作，不按开发批次分类。

设计参考了 [Notion 账户与偏好设置](https://www.notion.com/en-gb/help/account-settings) 的职责拆分、[Linear 工作空间设置](https://linear.app/docs/workspaces) 的上下文分类，以及 [Todoist 导航定制](https://www.todoist.com/zh-CN/help/todoist/features/customize-the-sidebar-and-navigation-menu-in-todoist-S9JLTYqZV) 和 [Notion 侧栏](https://www.notion.com/help/navigate-with-the-sidebar) 的常用入口与次级工具组织方式。这里采用的是适合个人应用的分组、渐进展开和移动返回路径；没有引入组织权限或工作空间切换。

主要实现：`settingsCatalog.ts` 和 `navigation.ts` 集中目录；`SettingsModal.vue` 管理搜索、焦点和手机返回；`interface-settings.css` 管理各套设置风格；各设置组件按账户、隐私、同步和备份拆分。验证脚本为 `verify-settings-product.mjs`、`verify-product-navigation.mjs` 和 `verify-settings-native.mjs`。浏览器矩阵、隔离 Windows 原生、模拟平台分支分别记录，不相互替代验收结论。
