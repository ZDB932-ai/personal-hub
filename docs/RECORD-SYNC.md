# 逐条同步引擎 · 第四阶段

第四阶段完成客户端同步闭环及无服务器演练。第五阶段已接入可在本机运行的真实 HTTP 服务，详见 [SYNC-SERVER.md](./SYNC-SERVER.md)。用户业务数据不会发送给演练服务；只有主动连接真实服务才会联网同步。

## 使用与验证

「设置 → 同步 → 本机同步演练」使用独立的三台虚拟设备、随机密钥和示例记录，检查不同记录合并、同记录冲突、丢失回执、重建客户端后的重试与删除传播。演练只在内存中运行，关闭页面即丢弃，不读取真实保险库，也不监听端口。

真实保险库的状态适配已接入 `xk-vault` IndexedDB 事务。冲突列表与选择界面位于同一设置页，仅在真实队列中存在冲突时出现。默认隐藏内容；展开可能显示密码，锁定和关闭设置会收起内容。选择本机版本会创建一个基于已知远端版本的新操作；选择另一设备版本会替换该条本机记录。选择保存失败时保留双方。界面尚无字段级合并和“同时保留两个副本”。

本阶段验证：12 个测试文件共 113 项通过，`npm run build` 通过。Edge 隔离测试环境已验证演练不写入真实保险库、冲突内容默认隐藏、选择远端版本后保存及刷新解锁后保持结果，未发现页面运行时异常。尚未进行 Android/Windows 安装包验收。

## 引擎与接口

- `recordSyncEngine.ts`：与存储、网络实现分离的客户端状态机。
- `recordSyncWire.ts`：协议 v2，绑定 vaultId/keyId 的 AES-GCM 加密操作与解密校验。
- `syncMerge.ts`：记录验证、增量合并、删除与冲突选择；保留本机提醒状态和附件路径。
- `recordSync.ts`：真实保险库适配，仅允许已解锁 v3 保险库；提供手动运行和可解除的自动同步会话。
- `recordSyncScheduler.ts`：修改后合并触发、网络恢复/前台唤醒、退避重试。第五阶段由 `recordSyncSession.ts` 在用户成功连接 HTTP 服务后调用 attachRecordSync。
- `syncRehearsal.ts`：独立的密文模拟服务与加密快照设备，仅用于演练和测试；不具备认证、持久化服务端或生产安全边界。

实际传输需要实现 `RecordSyncTransport`：稳定 serverId、push(space, wire)、pull(space, cursor)。serverId 需要绑定服务实例和数据集，不能仅按用户可修改的 URL 随意替换。当前 journal 同时绑定 serverId/vaultId/keyId，更换范围会拒绝复用旧游标和记录版本。

同步消息不携带主密码封装、主密码或业务明文。服务端可见实体标识、操作标识、设备标识、基础版本和删除标记；内容加密，包含同一份元数据和数据空间标识，客户端解密后验证一致。不能将 deviceId 当成认证凭据。当前客户端仍依赖服务端正确排序和保留历史，不构成抵御恶意服务端所有回滚/遗漏行为的证明。

## 持久化状态与顺序

`offlineJournal.sync` 与业务数据一起加密保存：

```
{ scope, cursor, inFlight?: { operation, wire }, failures, retryAt, lastError }
```

1. 同一存储同时最多一个同步运行。解锁、密钥和数据更新状态发生变化时停止后续处理。
2. 若有在途操作，先重发其原始操作 ID 与原始密文，确认落盘后才拉取或发送后续操作。
3. 按页拉取。页内全部密文校验、合并结果、冲突与新游标一次提交；验证或提交失败不推进游标。每页最多 500 条，每次最多拉取 100 页。
4. 从无冲突记录选择下一操作，加密完整请求并先持久化为 inFlight，再调用传输接口。
5. 接受回执后原子保存版本、清除该在途请求。上传期间产生的更新保留为另一个操作，并更新其基础版本。
6. 网络异常保留在途请求，保存 1 秒起、最大 60 秒的指数退避；调度器读取 retryAt 后重试。解锁后能延续持久化状态；无意义的空跑和等待用户处理的冲突不会无限重试。每次最多发送 100 条，剩余工作可继续调度。

语义相同的初始设备副本可直接接受远端已存在版本，不制造重复更新；不同内容保留本地和远端双方。删除记录保留墓碑，长期离线设备的编辑不会悄悄复活已删除记录。每个集合的单例作为一条记录处理，不做内部字段自动合并。

## 应用并发与恢复

真实数据库适配与自动保存共用串行队列，提交前检查内存修订状态。加密等待期间的新编辑会中止该次提交；事务已提交、发布前发生的新编辑会合并回内存并再次保存。保留其他独立远端记录。跨窗口写入仍使用 IndexedDB 修订标识拒绝覆盖，需要先导出本窗口副本再刷新。

普通备份恢复使用目标保险库的当前同步日志作为基线，把恢复后的内容计算为本机修改，不引入备份来源的服务端游标。新设备加入重新建立设备身份与待同步操作，不复制源设备的在途请求。
