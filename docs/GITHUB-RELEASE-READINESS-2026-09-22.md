## 发布前优先解决

### 1. 提醒在锁定后的行为不完整

静态调用链：`lockApp()` 调用 `wipeMemory()`，后者把 `tasks.value` 清空；Android 的深度任务 watcher 仍绑定，随后 `rescheduleNative()` 先 `cancelAll()`，再从空任务列表生成计划。因此存在锁定后清除已安排原生提醒的明确代码路径，需要真机复现并修复。

Web/Windows 在 `isGated` 后停止提醒扫描，当前不能承诺锁定后仍准时提醒。Android 调度另外直接截取前 60 条、没有按提醒时间排序，较近任务可能因数组顺序排在截断范围之外；调度失败被空 catch 吞掉。Web/Windows 也会在通知成功确认前更新已提醒标记。

建议：锁定与用户删除任务分别处理；明确锁屏通知是否隐藏标题；按到期时间选取提醒；调度失败可见并允许重试。验收至少覆盖自动锁定、拒绝权限、超过 60 条、进程重启和 Android 后台行为。依据：`src/stores/lock.ts`、`src/stores/database.ts`、`src/App.vue`、`src/lib/reminders.ts`。

### 2. 缺少公开项目入口

根目录没有 README、LICENSE、CHANGELOG、SECURITY 或 CONTRIBUTING。AGENTS.md 是工程上下文，不能代替使用说明。

首版至少补齐：产品定位、截图、功能与限制、下载/构建步骤、Node 24 与原生环境要求、备份与升级说明、反馈入口、版本说明。代码许可证需要由项目所有者选定，不在本次擅自添加。另为壁纸、宠物模型、参考图、图标和第三方组件建立来源及允许发布范围清单；当前未找到覆盖这些随包素材的完整说明，不能据此认定其发布权限已确认。

### 3. 整理实际提交范围

根目录两个未忽略 QA 文件约 60 MiB：`phone-1789871086479.bin`、`qa-windows-save-50-1789878781111.bin`。宠物目录含多版 .blend、.blend1、实验 GLB、截图及日志；其中两个 source.blend/source.blend1 各约 59.89 MiB。scripts 下也有预览日志。

建议使用明确的发布文件清单：保留运行资源、代码、必要文档和测试；测试落盘文件与运行日志加入忽略；可编辑模型和实验档案单独保留或另行管理。不要直接 `git add .`，也不要为减小仓库直接删除唯一美术源文件。签名材料已经有忽略项，但正式公开前仍需检查暂存区和 Git 历史。

### 4. 最终安装包与当前代码对齐

`RELEASE-VERIFICATION.md` 有历史 Windows 升级、Android 测试包覆盖更新及签名检查记录；`PET-HANDOFF.md` 明确最新宠物只构建了 exe，未生成新安装包。历史报告还注明 Android 包未含后续确认逻辑修复。

因此不能把现有目录中任意 APK/NSIS 作为本次最终包。应确定版本与提交后重新构建，记录 SHA-256，使用隔离数据验证安装、升级、解锁、备份恢复、导出取消、提醒和退出。Windows 历史安装包为未签名状态；发布说明应据实标注。已有升级验收不能泛化为当前所有改动已验收。

### 5. 修正与实现不一致的说明

- 关于页写“主密码永不落盘”，但 `biometricStoreSecret(password)` 在开启指纹后把密码交给原生安全凭据存储。应说明默认只在内存使用、开启指纹后由系统安全存储保护凭据，避免绝对化表述。
- `src/lib/sync.ts` 仍有“逐条同步服务尚未接入”的旧提示，而当前已经存在对应实现。
- AGENTS.md 仍写未配置托盘，当前 `src-tauri/src/lib.rs` 已配置托盘与关闭隐藏行为。
- 多个历史文档存在“尚未接入”与后续补充并列。应有一个当前功能状态入口，历史验收注明适用版本。

### 6. 让其他电脑能够复现

`android/gradle.properties` 固定使用本机 `E:/phub/.jdks/jdk-21`，`scripts/verify-today-simple.mjs` 固定使用 `C:/Users/ZDB/.../playwright`。package.json 未声明 Playwright；其他验收脚本允许环境变量指定外部模块，尚未形成完整的新机器安装流程。

CI 已有类型检查、服务端类型检查、单测和 Web 构建，但没有固定浏览器的 UI 验收，也没有 Windows/Android 发布包构建链。优先让全新目录 `npm ci` 后能复现基础验证，再逐步纳入关键 UI 流程；无需为首版自动化所有美术验收。

## 可在首版之后完善

| 项目 | 当前问题 | 建议优先级 |
| --- | --- | --- |
| 存储清理 | 删除及清空历史后，附件密文可能仍占空间；跨库事务中断也可能遗留未引用附件 | 高：增加引用分析、空间统计、可确认的安全清理 |
| 备份引导 | 手动导出已有；缺少统一的新用户备份引导和最近备份提醒 | 高：首版文档先说明，后续增加界面提示 |
| 剪贴板体验 | `copyText` 的 execCommand 回退未检查布尔结果，失败仍提示成功；未发现定时清除机制 | 中：先修准确反馈，再设计平台允许范围内的敏感复制清理 |
| 密钥使用体验 | 新建 v2 与手动升级 v3 两条路线并存 | 中：评估新库默认 v3；保持旧库兼容，不为发布仓促改迁移 |
| 大量数据与包体 | 单个业务快照保存；3D 分包较大；public 仍有历史宠物资源 | 中：测大库保存与低配置设备，再清理无生产引用资源 |
| 桌面宠物 | 多显示器/DPI/长时间运行未综合验收，肩肘、眼周与滑步仍有已知边界 | 中：首版作为默认关闭的实验功能，后续独立优化 |
| 正文搜索 | 限文本/PDF，单文件 10 MiB、前 200 页、10 万字符，会话结束清空 | 低：明确限制即可，OCR/Office 搜索不阻塞首版 |
| 大视图维护 | TodayView、AiView 等仍集中较多逻辑 | 低：下次业务修改时分拆，避免为首版做全面重构 |

## GitHub 展示站单独注意

如果“发布”还包含仓库子路径下的网页演示，当前 Vite 没有配置 base，图标、壁纸、宠物资源多处使用 `/...` 根路径。hash 路由只解决路由层，不能解决静态资源子路径。需要单独适配并实际验收；单纯公开源码或附安装包不受此项影响。

## 建议首版范围与顺序

首版定位为“本地优先的个人管理工具预览版”：计划、备忘录、资料、密码库、项目收藏、搜索、备份恢复为主；AI 工作台和桌面宠物明确标记为可选/实验能力。同步描述为需要自行配置的可选能力，不等待服务器部署。

1. 修提醒链路和失实文案，增加对应回归验证。
2. 建立 README、截图、发布说明、素材清单，确定代码许可与提交范围。
3. 处理本机固定路径，验证干净检出可构建、基础 CI 通过。
4. 冻结版本与提交，从该提交重新生成安装包及校验值，完成关键原生验收。
5. 配置目标 GitHub 仓库，推送源码并发布预览 Release。

本次完成的是项目盘点与发布差距整理；上述修复、许可证选择、包构建和远程发布尚未执行。
