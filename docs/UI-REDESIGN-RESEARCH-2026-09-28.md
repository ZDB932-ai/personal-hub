# 全界面改版研究 · 2026-09-28

## 目标与结论

用户明确选择：**每天打开就清楚该做什么，任务和日历优先**。

推荐以「今天 → 安排时间 → 开始任务 → 留下进展」为主流程。全局导航、页面标题和详情操作遵循同一套规则，资料、密码与开发工具作为稳定可找的辅助入口。保留现有暖白纸感、主题和壁纸能力，先解决职责、层级与信息密度。

本文是研究与设计提案，尚未修改生产界面或替换 `design-system/MASTER.md`。这里的布局建议是结合项目的设计判断，不是已验证的用户行为结论，也不代表照搬参考产品。

## 推荐的信息架构

```text
Personal Hub
  全局搜索                       固定入口，继续支持 Ctrl+K

  日常
    今天                         默认首页：继续任务、今日清单、接下来时间
    日历                         日/周/月排期，按需查看待安排和详情
    计划                         待安排、本周、长期方向、全部任务
    收集箱                       想法与未整理便签，明确内容类型
    回顾                         完成记录、项目进展、一天收尾

  内容
    备忘录
    资料库
    密码库

  开发工具                       可折叠
    仓库
    AI 工作台
    Agent 资源库

  个人资料 / 设置 / 同步状态 / 锁定
```

这是一份导航提案，第一轮无需创造新业务类型。现有路由可以通过别名、重定向和查询参数继续兼容，现有数据关系保持不变。

“收集箱”与计划里的“待安排”职责必须说清：收集箱处理尚未整理的想法/便签；待安排是已经明确为任务、尚未选日期的记录。把想法转成任务后显示来源与去向，避免两处看似重复。

“计划”保留频率、长期方向和全部任务管理，不再额外维持第二套“今天”工作台。专注是从任务进入的工作模式；保存线索、完成和返回来源仍可直接操作。

## 首页与日历构图

### 今天：先知道下一步

桌面主栏占主要宽度，次栏只放今日时间安排。页头是“今天 + 日期”，避免问候、眉题、说明重复占空间。

1. 有未完成且有效的继续线索时，展示任务名、下一步一句话、唯一醒目的“继续”按钮。推荐不能自动替用户更改排期。
2. 今日任务按重点、定时、其他组织；显示标题、时间/预计时长和必要状态，不把每一项做成大卡片。
3. 右侧摘要显示接下来的定时任务和可用时间，进入日历查看完整坐标；不重复任务操作工具条。
4. 逾期处理使用单行提示与明确入口；已完成默认折叠；“一天收尾”位于页面末尾或回顾入口。
5. 没有任务时只突出添加一件事，允许当天留白；没有时间安排时次栏提供简短入口，不堆多个空态框。

### 日历：专门解决何时做

使用稳定全局导航、日期工具栏、主画布。迷你月历与待安排入口放在可折叠的日历导航区；右侧按需打开单一详情面板，避免便签、方向、详情三种面板同时挤压画布。

保留现有半小时创建、重叠分列、短任务最低点击高度和保护留白的业务能力。周/月/日切换与当前日期范围始终可见。时间已满时给出事实提示和用户选择，不自动顺延任务。

### 手机

建议底部保持“今天 / 日历 / 收集 / 更多”四项；计划、回顾和所有资料仍可从更多进入。当前选中模块应在更多按钮及面板中明确标识。

今日时间摘要进入可展开区，任务仍在前；日历默认日视图。详情使用单页或抽屉，保存后回到原日期、筛选和滚动位置。桌面密度不直接缩小套用到手机。

## 所有模块如何归一

| 模块 | 页面核心任务 | 推荐模板与保留能力 |
| --- | --- | --- |
| 今天 | 开始/继续今日任务 | 主清单 + 次要日程摘要；继续线索、重点、容量仍可用 |
| 计划 | 整理和分配任务 | 列表模板；本周排期、长期方向、待安排、完成记录入口 |
| 日历 | 看时间、安排时间 | 全宽画布；上下文详情；与任务列表使用同一记录 |
| 专注 | 做当前这一件事 | 显式进入沉浸模式；退出返回来源；继续线索与资料按层次展开 |
| 收集/回顾 | 整理想法、查看进展 | 列表与分组；复用现有灵感、完成、故事、收尾组件 |
| 备忘录 | 快速记录与回看 | 统一页头工具栏；保留卡片阅读和清单转任务 |
| 资料库 | 找到并打开文件 | 列表优先、可切缩略图；选中再出现批量工具；保留原生保存和正文搜索 |
| 密码库 | 找到账号并使用字段 | 列表 + 详情；手机单列进入详情；复制、TOTP、显隐和自动隐藏保持原语义 |
| 仓库 | 查找收藏和自己的项目 | 两个清楚的视图；搜索与筛选位置统一；连接状态弱化展示 |
| Agent 资源库 | 找到可用资源 | 类型、兼容 Agent 和用途是主要信息；筛选面板显示当前条件；不把携带资源说成安装成功 |
| AI 工作台 | 查看会话和操作进度 | 会话列表 + 工作内容 + 按需详情；仅整理界面，远程能力仍按已有要求暂缓 |
| 设置/个人资料 | 找到特定设置 | 稳定分类、明确标题、就近反馈；外观自定义和桌面宠物继续可达 |
| 锁屏/导入/恢复 | 清楚且可恢复地完成操作 | 保留原流程与确认语义，统一表单和反馈样式；不为视觉简化丢失错误信息 |

## 设计系统的实施约束

- 沿用 `surface/line/primary/t1–t4` 和语义状态色；当前默认色来自 `src/style.css`，不直接复制其他产品色板。
- 页面、工具栏、任务行、详情的间距分别统一，使用现有 4px 基数；卡片与控件沿用 12px / 8px 基线，各风格例外集中管理。
- 先用留白和对齐分组，再决定是否需要边框；列表/详情模板与当前“重复条目独立卡片”规范的冲突，必须在正式实现时同步修改 MASTER，不能悄悄违反。
- 普通页遵循同一页头和工具栏；时间画布允许占满可用宽度，但不更换导航体系。
- 主按钮按当前任务决定，不规定永远是新增；选中、错误、焦点不只靠颜色区分。
- 不减少正文对比度来制造清爽；不把所有高级能力藏进无文字图标；不把需要持续查看的信息都塞入弹窗。
- 中文名称优先表达用途；“孵化”“回廊”等可作为辅助表达，避免承担唯一的导航含义。

## 建议实施顺序与验收

| 阶段 | 可交付变化 | 完成条件 |
| --- | --- | --- |
| 1 | 全局壳层、默认今天页、首页任务层级 | 解锁后首屏看到今天和下一步；搜索/新建/锁定位置稳定；旧路由可用 |
| 2 | 计划、日历、专注联动 | 同一任务的查看、排期、开始、完成、返回连续；不产生重复任务；保留日期与筛选 |
| 3 | 资料/密码/备忘录/仓库/Agent 列表模板 | 工具栏、筛选生效提示、详情、空态与批量选择行为一致 |
| 4 | 设置、错误状态、多主题与三端收尾 | 所有功能有去处，离线/保存失败/锁定可识别；按平台验证并分别报告 |

先拆分大视图的展示和交互组合逻辑，再迁移模板；本次没有要求更改存储与同步协议。

验收任务：从今天继续上次任务；在日历安排未定时任务；捕获想法再转任务；找到资料并关联任务；查找账号复制字段；完成任务并回顾；锁定、刷新解锁后状态仍正确。

验收尺寸至少 375/768/1024/1440；覆盖浅/深色、现有四种风格和壁纸开关。覆盖空白、常规、长标题、多标签、较多任务、保存失败、离线状态。关键控件触控目标遵循现有 44px 要求，键盘焦点可见、弹层可退出。正式改代码后必须运行 `npm run build`，交互和数据相关改动执行适当现有测试。

首屏层级和完成任务路径应通过实际操作比较；没有用户测试前，不声称减少了某个百分比的认知负担或提高了效率。
