## 优先修复

1. **修改历史被继续线索占满（高）**。saveResume 每次输入都会修改任务；数据库停顿 400ms 后落盘，captureRecovery 为不同线索版本各存一条任务快照。历史和回收站共用 200 条上限，没有按条目合并。隔离实验模拟 201 次保存，最终 200 条全部是同一任务的历史，原来一条尚未过期的已删便签恢复记录被挤出。建议合并同一编辑会话的历史，并分别保留删除记录和修改快照。

2. **灵感草稿的离开保护不完整（高）**。FocusView 的 draft 只在组件内存，路由守卫只保护路由切换；自动锁定、托盘锁定走全局 lockApp，不经过页面 savePocket。App 在 isGated 时卸载页面，刷新同样丢弃内存。完成、暂停、页面自带锁定已处理，但不能覆盖以上路径。建议引入统一加密草稿与锁定前提交机制；不能以明文 localStorage 补救。本项由代码路径确认，本次新增浏览器复现未完成。

3. **“已收好”早于成功落盘（中）**。InspirationPocket.capture 同步清空输入并显示成功，只修改内存；实际加密落盘由数据库延迟进行。存储失败时虽然有全局错误，组件仍保持成功状态。建议等待保存回执，失败保留可重试状态；区分“已收集”和“已保存”。本项为代码检查结论，未做磁盘失败浏览器注入。

4. **跨午夜容量与时间轴不一致（中）**。隔离实验中 23:30 开始、120 分钟的任务，时间轴在次日显示 90 分钟，而 dayLoad 次日为 0、开始日为 120。会影响容量提示及周排期。建议定时任务按实际跨日区间分摊容量，无时间任务仍归入指定日。

5. **继续线索无法搜索（中）**。searchHub 的任务索引只包含标题、备注、标签与子任务，未包括 resumeNote 和 resumeNextStep。隔离实验在继续线索中存入独有关键词，结果为 0。建议补齐索引并提供直达专注的结果入口。

6. **数据入口校验存在缺口（低）**。protectTime 创建路径拒绝无效日历日期，但 validateEntity 只匹配日期形状。隔离实验中同步/导入验证接受 2026-02-31；deferredUntil 也只检查字符串。建议创建、导入和同步共用真实日期校验，避免幽灵留白或方向异常隐藏。

## 产品与结构优化

- **分开工作容量和日历禁排时间。** 目前所有留白分钟都扣工作容量。实验加入 00:00–08:00 睡眠后，当日默认 180 分钟容量归零，尽管建议工作区间为 09:00–18:00。建议提供工作时间范围；区间避让和精力预算分别计算，解释两种含义。
- **补上灵感的回溯入口。** capturedFromTaskId 已保存，但界面没有读取并展示来源任务。灵感应展示“产生于哪件事”，原任务也可以回看相关灵感；来源已删除时给出明确状态。
- **减少重复选择。** 首页优先呈现最近继续的一个任务；专注入口先给少量候选，再允许展开全部。成果回廊和日历足迹共用查询和关联组件，减少以后出现规则差异。
- **完成后仍能查到继续线索。** 当前专注页在任务完成后隐藏原工作区；任务编辑和成果卡也不显示 resumeNote / resumeNextStep。建议保留只读查看入口，或在完成确认中允许把线索转入成果记录。
