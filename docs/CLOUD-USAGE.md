# 手机与电脑使用云同步

**1.1.6 起推荐云账号：首次注册，其他设备直接用同一账号密码登录，不再需要下面的文件步骤。完整说明见 [CLOUD-ACCOUNT.md](CLOUD-ACCOUNT.md)。以下保留为 1.1.5 及更早本机账户的操作记录。**

访问地址与逐条同步服务地址均为 `https://111.91.19.235`。必须使用 HTTPS；这是本地优先的加密应用，账户名称不是云端登录账号。

## 首次使用

1. 在电脑浏览器打开网站，创建本地账户和主密码，按页面要求单独保存完整恢复密钥。
2. 进入「设置 → 安全 → 设备独立密码」，验证本机主密码并生成设备加入文件。单独保存页面显示的转移码。
3. 手机打开同一网站，在尚未创建账户的首页展开「加入已有保险库」。选择电脑导出的 `.phub-device` 文件，输入转移码，并设置手机自己的主密码。手机端的设置入口位于「更多 → 设置」。
4. 在电脑和手机各自的「设置 → 同步 → 逐条加密同步」中填入 `https://111.91.19.235` 及同步访问令牌，点击「连接并同步记录」。不要使用旧版 PocketBase 的邮箱登录区域。
5. 电脑新增一个任务或备忘录，手机点击「立即同步记录」确认出现；再在手机修改，电脑同步确认。正常使用会自动推送修改，并在解锁且处于前台时每 45–60 秒拉取。

同步访问令牌通过 SSH 保存到本机 `.sync-data/cloud-111.91.19.235/access.local.json` 的 `token` 字段；该目录已被 Git 忽略。令牌不要公开、提交到代码仓库或放入网页资源。

电脑和手机应加入同一个保险库，不要分别创建两个账户后期待数据自动合并。设备文件与转移码应分开传递，完成加入后妥善处置。手机加入后可在安全设置启用该设备自己的恢复密钥，电脑的恢复密钥不会自动转移。

## 日常使用

Android/Windows 1.1.5 已预填服务器地址，可以在「设置 → 同步」选择「导入连接文件并同步」，导入本机 `.sync-data/cloud-111.91.19.235/Personal-Hub-private-sync.json`。连接文件包含访问令牌，应私下传到自己的手机，不要公开。第二台设备仍须先通过设备加入文件加入同一保险库。网页版 1.1.4 继续使用上面的手动令牌入口。

- 主密码可以不同，每次重新打开仍需解锁。服务器只保存业务密文；不能替你找回主密码。
- 连接配置在设备上加密保存，解锁后自动恢复。锁屏或手动暂停时停止同步；手机后台不保证持续同步。
- 手机可选择「打开时下载，保留已下载文件」减少附件流量；需要完整离线内容时选择全部下载并同步。
- 两端离线修改同一条记录可能产生冲突，在设置的同步区域查看并选择保留版本。
- 不要清理浏览器站点数据或在隐私浏览窗口中长期使用；服务器同步不等于本机恢复密钥或设备加入文件的备份。
- 从网页切换到 Windows/Android 原生应用时，也是一个新的设备存储，需要通过设备文件加入同一保险库。
- 本次实测发现本机系统代理 `127.0.0.1:7897` 链路下大附件请求超时；在同一电脑使用直连后完整通过。如开启代理，建议将 `111.91.19.235` 设置为直连。本次部署未改动系统代理设置。

## 服务器运维

- 项目：`/opt/personal-hub/current`；数据：`/opt/personal-hub/data`。
- 服务：`personal-hub.service`、`caddy.service`；同步仅监听 `127.0.0.1:8787`。
- 备份：`personal-hub-backup.timer` 每日北京时间 04:10 起随机延后最多五分钟执行，保留最近 7 份成功归档。复制数据库时短暂停止同步服务，网页仍可打开，客户端之后重试。
- 备份路径：`/opt/personal-hub/backups`。同机备份不能防止服务器整盘丢失；异地备份目的地尚未配置。
- Caddy 自动管理 IP 证书与续期，80/443 应持续保持可达。自动续期配置与首次签发已验证，未来续期是否成功仍以运行日志和证书为准。
- 同步进程内存上限 512 MiB，Caddy 256 MiB。SQLite 主数据库上限 2 GiB；WAL、备份和运行文件另占空间。附件仍按每保险库 1 GiB 限制。
- 初始传输保护为全服务每秒 60 请求、突发 120、并发处理 16、连接上限 128；超限返回 429。该配置适用于个人少量设备使用。

不要直接用旧数据库覆盖正在运行的服务。恢复时保留完整数据目录及 serverId；如果旧备份游标落后于客户端，需另行处理，不能伪造同步完成。
