# 设备独立密码与离线加入 · 第三阶段

后续更新：新本地账户已直接创建 v3，并支持预设本机恢复密钥。旧账户可在安全设置升级；下方“首次创建仍为 v2”是历史行为。详见 [本地账户与恢复](./LOCAL-ACCOUNT.md)。

本阶段无需服务器，提供 v3 密钥封装、旧库显式升级、独立设备密码和一次离线数据复制。尚未实现设备间持续同步、设备授权服务或远程撤销。

## 使用方式

1. 现有设备进入「设置 → 安全 → 设备独立密码」。先导出 `.phub` 备份，再输入本机主密码执行「升级并启用」。首次创建的保险库当前仍为 v2，使用同一入口升级。
2. 升级成功后，在同一区域验证本机主密码，生成 `.phub-device` 文件和随机转移码。文件包含当前业务数据和全部本机附件，不包含云同步、GitHub、AI 的设备连接凭据。
3. 在尚未创建保险库的新设备首页展开「加入已有保险库」，选择文件、输入 32 位转移码、设置至少 8 位的本机密码。
4. 加入完成后重新加载，使用新设备的本机密码解锁。两台设备的保险库 ID 和数据密钥相同，设备 ID 与待同步操作重新生成；之后各自的修改仍只保存在各自设备。

文件与转移码可重复使用，不具有服务端一次性消费、自动过期或撤销能力。组合泄露意味着数据密钥泄露，不能仅靠修改主密码撤销访问。界面明确提示分开传递、完成后删除；不自动发送文件或转移码。

## v2 与 v3

v2 保持兼容：主密码经 Argon2id 派生数据密钥。升级时生成随机 256 位数据密钥，将业务、附件与三类连接凭据重新加密一次；附件先暂存新 ID，再原子提交主信封和凭据。缺失附件会阻止升级；失败保留原密码、密文和附件。

v3 仍使用原 Repository 键 `xk.data.v2`，但信封明确标识 `v: 3`：

```
{ v: 3, vaultId, keyId, kdf, wrappedKey: { ivB64, ctB64 }, ts, ivB64, ctB64 }
```

主密码经 Argon2id 得到封装密钥，AES-GCM 保护随机数据密钥；业务和附件使用数据密钥加密。封装的 additionalData 绑定协议域、版本、vaultId 和 keyId。运行时数据密钥为不可导出的 CryptoKey；生成、解封和重新封装过程中短暂存在的原始字节缓冲区在 finally 中清零，不能声称 JavaScript 运行时具备可靠的全内存擦除能力。

v3 改密先保存业务修改，再重新封装同一数据密钥。业务密文、附件、连接凭据和业务时间戳不因改密改变；密码提示与封装在同一事务提交。旧密码不能打开新的封装，但仍可打开旧备份；其他已加入设备不受影响。真正的数据密钥轮换和设备撤销尚未实现。

KDF 输入在计算前限制盐格式、内存、次数和并行度，拒绝超范围文件，避免不受限的资源请求。默认 Argon2id 参数保持原值。

## 设备文件

外层只有协议标识、转移码保护的数据密钥封装、随机 IV 和密文。密文包含带用途标识的完整业务快照与附件密文列表；整包认证可检测附件列表和内容被篡改。转移码由系统随机数生成器生成 128 位随机数，以 32 位十六进制显示；它不是用户自选短密码。

接收端验证用途、保险库标识、数据密钥标识、附件认证和大小；暂存附件后原子提交本机封装与信封。只允许空设备加入，不覆盖既有保险库。事务失败清理暂存附件；中断可能留下未引用的附件，后续仍需垃圾回收。

普通 `.phub` 备份恢复到已有保险库时仍采用目标保险库的数据密钥与身份，属于恢复内容；设备加入则保留源保险库的数据密钥与身份，两者语义不同。

## 云同步与兼容

后续阶段已接入逐条记录及附件同步，最新三端验收见 `VERIFICATION-2026-09-20.md`，原生保存见 `NATIVE-FILE-SAVE.md`。以下“仍需后续实现”是第三阶段当时的状态。

生成设备加入文件时会检查数据与存储版本。附件较多、生成耗时较长时，后台同步可能改变版本，导致提示“生成期间数据发生变化，请重试”；这会拒绝不一致的导出。现在可先完成同步，在同步页点击“暂停同步”，待显示“同步已暂停”后生成文件，再点“恢复同步”；配置保留，无需重输令牌。

v3 不调用旧 PocketBase 整库同步，避免把某设备密码封装覆盖到另一设备。新的逐条密文协议、设备注册、权限、持久化在途操作和服务端冲突处理仍需后续实现。旧客户端不支持 v3，应关闭旧客户端后升级，不能直接降级继续使用。

原生 SQLite、Android/Windows 安装包、真机文件选择和下载体验仍需验证。本阶段不代表三端联网同步已经完成。
