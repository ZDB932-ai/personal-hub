# 本机事务存储 · 第二阶段

不需要服务器。主数据、离线队列和连接凭据仍只在本机保存。

## 当前实现

`src/lib/vaultRepository.ts` 定义异步 `VaultRepository`，默认实现为 IndexedDB。Web、Tauri WebView、Capacitor WebView 当前共用这一实现，尚未接入原生 SQLite。

数据库 `xk-vault` 的 `state/current` 保存版本号、随机修订标识及以下键：

- `xk.data.v2`：原 v2 AES-GCM 信封，包含业务数据和离线队列。
- `xk.sync.secure`、`xk.github.secure`、`xk.ai.secrets.v1`：原有加密连接凭据。
- `xk.lock.v2`：非秘密的密码提示和自动锁定偏好。

加密格式不变，主密码和解密后的业务内容不写入数据库。主题、服务器地址等普通配置仍在 localStorage；附件仍在 `xk-docs`，壁纸仍在 `xk-wallpaper`。

Repository 当前操作的是整个加密快照，不是逐条实体数据库。原生适配器将实现相同的 load/initialize/commit 契约；逐条密文表、附件表和云端传输仍需后续扩展。

## 启动迁移

1. 在加载业务模块前，恢复旧 localStorage 改密回滚日志。
2. 优先读取已存在的事务数据库。仅在数据库无当前记录时，解析旧存储的上述五个键。
3. 在一个事务中写入当前记录与 `migration-backup` 迁移检查点。两个窗口竞争初始化时使用先提交的版本，不覆盖已有数据。
4. 重新读取确认提交后清理旧键，再进入应用。解析失败、事务失败或检查失败时停止启动，避免误进入空白新库。
5. 第一笔正常事务提交后删除迁移检查点；它不是长期备份。迁移清理中断时，重启仍优先使用已经提交的数据库。

迁移不兼容旧客户端继续写 localStorage：升级前应关闭旧版本窗口，不要在同一浏览器来源同时运行两个版本。不要通过降级旧包读取更新后的数据；使用新版本导出的 `.phub` 备份恢复。

## 提交与并发

同窗口写操作串行执行。IndexedDB 的 readwrite 事务内检查修订标识，并原子替换当前记录；只有 transaction complete 后才更新缓存和业务保存状态。旧窗口保存会抛出 `StorageConflictError`，不会覆盖另一窗口已提交的数据。

页面持续显示保存失败信息。用户可导出当前窗口内存中的加密恢复副本，再刷新载入最新版本。副本不包含其他窗口的最新修改，也不表示冲突已合并。恢复副本仍是整库替换，不能直接当作自动合并使用。

改密将主信封、三类加密凭据和锁定偏好一次提交。附件先写入新 ID，成功后才切换元数据；事务失败清理暂存附件。恢复备份也采用暂存附件与单次信封提交，不再先存旧密码信封再二次改写；附件解密失败会终止恢复。

附件数据库与主数据库不是跨库原子事务：崩溃可能留下未引用附件，后续需做安全垃圾回收。恢复备份后原有附件暂留，避免提前删除导致不可恢复；当前没有自动垃圾回收。此行为不会让旧元数据覆盖新事务。

重置清空当前内容并更换修订标识，保留空库标记，阻止仍打开的旧窗口把旧内容再次写入。启动错误不会自动清空任何数据。

## 验证与边界

自动化测试使用 `fake-indexeddb`（仅开发依赖），覆盖并发初始化、同版本竞争写、真实事务中止、迁移失败/重试、来源损坏、清理中断、重置后防复活、模块重载恢复、冲突备份、改密与恢复失败。

已在独立的 Edge 无头浏览器上下文验证生产构建：首次启动、创建主密码、保存任务、两个窗口冲突、恢复副本下载、刷新与重新解锁；未报告页面运行异常，未使用个人浏览器数据。

需要继续做 Android / Windows 安装包和真实设备验证。当前没有部署云服务，没有 SQLite 驱动，没有新增网络权限。第三阶段已加入可选的密钥封装和离线设备加入，见 [DEVICE-KEYS.md](./DEVICE-KEYS.md)。

IndexedDB 事务行为参考 [MDN：complete 事件](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event)与 [IndexedDB 规范](https://www.w3.org/TR/IndexedDB/)。事务完成不等于抵御所有硬件故障，仍需独立备份。
