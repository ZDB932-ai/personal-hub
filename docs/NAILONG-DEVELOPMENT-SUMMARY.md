当前阶段已收尾，统一入口见 [交接索引](PET-HANDOFF.md)，其中列出最终资产、已验证范围与未解决问题。

2026-09-22 更新：最新精修入口为 `assets/pet-models/tripo-fixed/nailong-expression-polish.blend`，新增 Dance 和 Peek，共八段动画。「偷看被发现」已接入网页；肩部平滑候选因部分姿势劣化而撤回。权重、步态、验证及桌面构建情况见 [PET-MOTION-POLISH.md](PET-MOTION-POLISH.md)。下文保留此前记录。

记录日期：2026-09-21。本文件总结本次会话的开发过程、当前实现和维护注意事项。构建成功、自动化测试通过与真实桌面视觉验收是不同层次，不应混用。

## 1. 目标与当前状态

目标是制作可自主启停、可后台陪伴、可拖动、可提醒用户的桌面奶龙宠物，外形参考用户提供的奶龙图片，并具备自然、协调、有趣的互动动作。

目前采用用户提供的 Tripo GLB 为模型基础，结合 Blender 骨骼动画、局部形态键和 Three.js 动画混合，在 Tauri 独立透明窗口中运行。网页提供互动预览。

当前已形成可运行版本，但模型细节与动作协调尚未达到最终完成状态。主要未完成项是眼周接缝、完整面部结构、跑步脚底匹配，以及长时间桌面运行和跨屏行为验收。

## 2. 开发流程回顾

### 2.1 代码生成模型阶段

最初使用代码生成几何体搭建角色，逐步调整头、脖子、胳膊、腿和身体连接。这种方式适合快速验证交互，但外形精度有限。

出现过的问题包括：

- 几何体拼接感明显。
- 过度融合后胳膊与身体粘连。
- 头部过圆，修形后又出现尖顶。
- 身体和肢体比例偏离参考图。
- 动作以整体摆动为主，显得僵硬。

经验：角色辨识度依赖整体轮廓、比例与局部结构，不能单靠增加几何体或反复平滑解决。

### 2.2 参考图片与 Tripo 模型接入

用户提供了奶龙参考图片，随后提供 Tripo 生成的 `modela923d530b57701.glb`。后续改为在该模型基础上修复与精修，保留原始颜色贴图和 UV。

接入时曾出现网页模型有颜色、桌面模型发灰的问题。渲染端调整了 GLTFLoader 的纹理加载方式，使用 TextureLoader，并检查材质是否缺失颜色贴图。这部分兼容处理不能随意移除。

### 2.3 骨骼与动画阶段

从主要依赖代码摆动，逐步转向 Blender 骨骼动画。骨架由早期版本扩展为 17 根骨骼，覆盖身体、胸部、脖子、头、双臂、前臂、手、双腿、脚和尾巴分段。

当前六段动画：

| 动画 | 用途 |
| --- | --- |
| Idle | 待机 |
| Walk | 左右巡游 |
| Run | 快速前往目的地 |
| Wave | 打招呼、开心回应 |
| Eat | 吃东西 |
| Shy | 害羞 |

曾修正挥手牵动身体的问题，并调整摆臂幅度、头部配合、脚步支撑和动作过渡。捂脸动作曾做实验，但出现拉伸与折叠；用户随后转向整体精修，该实验未作为正式效果保留。

### 2.4 Blender MCP 局部精修

用户明确希望通过 Blender MCP 继续修改。后续在实时 Blender 工程中进行局部修改、渲染对比和导出。

MCP 是操作 Blender 的通道，当前实际操作仍通过 Blender Python 执行，不应描述为人工笔刷雕刻。

已完成的局部改动：

- 新增 CheekContour 形态键，微调脸颊和下巴，默认权重为 1。
- 将皮肤、眼睛、口部分为三个材质区，保留颜色贴图和 UV。
- 单独调整眼睛反光，排除眼周黄色皮肤，避免亮面扩散。
- 修正闭眼时眼角斜向折痕。
- 新增四个独立上下眼睑网格，并绑定 head 骨骼。
- 补充眼睑分段修正形态，减少闭合途中穿进眼球表面的问题。

重要限制：眼球仍在原融合网格内，独立的是眼睑，尚未重建独立眼球、眼球转动骨骼或完整面部拓扑。闭眼时仍可见眼周边界。

### 2.5 桌面交互和导航

逐步加入启停、后台陪伴、提醒、拖动、喂食、跳舞、害羞、睡眠等交互。

最近的调整：

- 左键拖动位置，右键左右拖动旋转。
- 移除菜单中的旋转滑块和旋转按钮。
- Home 恢复正面，方向键提供旋转操作。
- 去掉角色按钮周围的大面积焦点外框。
- 桌面菜单向角色侧边展开，右侧空间不足时向左展开；网页菜单位于角色下方。
- 朝向沿最短角路径变化，并限制转向速度，避免累计角度引发绕远路旋转。
- 取消随机自动转圈，保留主动触发的“开心转圈”。
- 巡游保留浮点坐标，最后设置窗口位置时才取整，修复边缘低速停滞。
- 巡游到边缘后短暂停顿再折返。
- 支持 Shift＋左键或中键从角色拖向目的地，松手后跑过去；也可先选择“指定目的地”再拖动。
- 指定目的地到达前减速，菜单、选点和手动交互暂停移动。

指定地点目前限定在当前显示器工作区。它采用从角色开始的拖动选点，不是全桌面任意点击捕获。

### 2.6 跑步节奏调整

通过 Blender MCP 基于 Walk 创建独立 Run 动画，增大步幅和摆臂，并在运行时按速度混合两段动画。手臂与腿使用同一动画相位，步相按移动距离累计。

用户反馈步频和摆臂过快后，快速奔跑动画频率统一降低约 25%，慢走到快跑之间平滑过渡；实际窗口移动速度不变。

这属于观感调节。移动速度不变而步频降低，会降低脚步与地面位移的严格匹配程度，后续仍需观察滑步。

## 4. 模型维护注意事项

### 4.1 保持源工程一致

当前以 `nailong-mcp-detail.blend` 为准。不要直接运行旧 `scripts/animate-tripo.py` 覆盖发布资源：它从旧源重建，会丢失 MCP 后续的材质、脸颊和眼睑修改。

修改前保留可恢复版本，每次只处理明确的局部问题，避免全身平滑导致已经确认的轮廓和权重退化。

### 4.2 导出不能漏掉眼睑

当前角色包含主网格及四个眼睑网格。导出时选择全部角色网格和骨架，排除摄影灯和相机，保留六段 Action、贴图、材质、骨骼权重和形态键。

导出前恢复中性状态。CheekContour 默认值保持 1；其他表情和眼睑修正键通常归零。不要把所有键统一清零而丢掉脸颊修形。

### 4.3 眼睑驱动约定

- 主网格原 Blink/BlinkLeft/BlinkRight 保留名称，但已经停止挤压眼球。
- 独立眼睑通过 BlinkLeft 或 BlinkRight 控制。
- LidArc1–7 对应每 1/8 闭合位置的曲面修正。
- 运行时混合相邻修正键，不能简单让全部修正键同时为 1。
- 害羞、眨眼和睡眠应共用一致的眼睑驱动。

### 4.4 动画协调

手臂和腿保持统一相位。跑步速度、动画频率、步幅和支撑时间需要一起评估，不能只增加摆动幅度。

检查动作被拖动、旋转、菜单或其他动作打断时的恢复行为，避免残留旋转速度、旧目标和动作权重继续影响角色。

## 5. 桌面行为维护注意事项

- 使用逻辑尺寸与物理坐标时正确处理显示缩放比例。
- 计算过程保留浮点位置，仅原生窗口提交时取整。
- 菜单展开会改变窗口宽度，关闭后需要恢复位置和移动边界缓存。
- 指针事件结束、取消和丢失捕获都要清理拖动状态。
- 异步处理前保存事件目标，不能在 await 后继续依赖 event.currentTarget。
- 对角度使用最短路径插值，避免从累计多圈角度回到行走朝向时高速旋转。
- 长时间暂停后限制时间步长，避免恢复时突然跨越大段距离。
- 网页预览不能代替原生透明窗口、缩放比例和屏幕边缘的实机验收。

## 6. 构建与验证

修改代码后必须执行：

```powershell
npm run build
```

相关测试示例：

```powershell
npm exec vitest run src/lib/__tests__/petNavigation.test.ts src/lib/__tests__/petPersonality.test.ts src/lib/__tests__/petGait.test.ts src/lib/__tests__/petRoaming.test.ts src/lib/__tests__/petMotion.test.ts
```

桌面测试版嵌入构建资源，需要在网页构建完成后重新编译：

```powershell
cargo build --manifest-path src-tauri/Cargo.toml --features tauri/custom-protocol
```

桌面测试程序为 `src-tauri/target/debug/personal-hub-desktop.exe`。这里的编译不等于生成正式安装包。

已遇到的环境问题：Vite 监听桌面编译目录时，会因被占用的 DLL 报 EBUSY 并退出。`vite.config.ts` 已排除 `src-tauri/target` 的监听。若使用 dist 静态预览，源码改动必须重新构建才能显示。

本轮导航相关 17 项测试通过，网页与桌面构建通过；最近的跑动降频调整也已构建并启动桌面测试版。此前已在网页检查睡眠闭眼和害羞切换，不能据此声称全部动作或长时间桌面运行均已验收。

## 7. 后续优先事项

1. 实机连续验证左右折返、目标停靠、菜单开关及交互打断，检查残留移动和状态竞争。
2. 观察降频后的滑步程度，结合步幅、移动速度和脚底支撑进一步调整。
3. 精修眼周接缝、闭眼轮廓与不同角度的贴合。
4. 检查挥手、害羞、吃东西与待机之间的连续切换。
5. 需要时再设计跨屏选点和移动规则，当前不视为已支持。
6. 如继续提升面部质量，考虑完整眼部结构与局部重拓扑，避免持续叠加形态修正。

建议持续采用：明确问题 → 保留备份 → 局部修改 → 多姿态与多角度对比 → 导出结构检查 → 应用接入 → 桌面实测。保留经过验证的改善，不把实验结果或构建成功直接当作最终完成。
