# 邮箱验证码恢复方案（待确认加密边界及发信配置）

目标：手机、Windows 和网页绑定同一个经过验证的邮箱，忘记密码后输入邮箱、验证码和新密码，无需另外保存恢复密钥。现有账号和业务数据保留。

## 用户流程

1. 已登录用户进入「设置 → 安全 → 绑定恢复邮箱」，输入当前云密码、邮箱和邮件验证码，完成一次绑定。
2. 忘记密码时输入绑定邮箱、收到的验证码和新密码，自动恢复原保险库并同步。
3. 更换邮箱需要当前云密码及新邮箱验证；旧邮箱收到变更通知。绑定邮箱必须唯一，邮箱是否存在不通过匿名接口泄露。
4. 旧的恢复密钥路径在迁移期间保留。没有经过邮箱验证及明确启用托管恢复的账号，不上传可由服务器恢复的数据密钥。

## 必须确认的加密边界

现有系统的服务器只有密码封装和密文，邮箱验证码不能推导原业务密钥。若要做到「忘记密码且没有其他设备/恢复密钥，仅凭邮箱就能恢复原数据」，本方案需要服务器托管可恢复的数据密钥副本。

拟采用专用服务器恢复主密钥加密托管副本，和数据库分开存放、限制文件权限，普通同步仍传密文。但服务器掌握解密能力：取得服务器恢复主密钥及数据库的人能够解密托管账号的数据，不能继续宣称服务器无法解密。单独存放在同一台服务器不等同于隔离服务器失陷风险。

只有在用户接受此变化后才实施和启用托管恢复。若用户不接受，则邮箱只能验证账号身份；恢复原数据还必须依赖已解锁设备或独立恢复秘密，无法满足纯邮箱恢复的全部要求。

## 验证码与恢复事务

- 验证码以安全随机源生成，10 分钟有效；数据库只保存与服务端秘密绑定的摘要。单次最多 5 次错误尝试，60 秒发信间隔，并设置邮箱及来源限流。
- 验证码按绑定、更换邮箱、恢复密码等用途隔离，绑定账号/邮箱和版本；重复发送不能重置累计暴力尝试额度。
- 只有验证码校验通过才签发短期、单次使用的恢复授权。重设密码原子更新封装、认证值与版本，消耗授权并撤销旧同步会话。
- 保持 vaultId/keyId 和业务数据密钥不变，保留离线待上传记录；服务端不记录原始密码、验证码或恢复密钥。
- 本机仍需联网用新密码登录一次更新封装；不能远程撤回离线设备已持有的数据或密钥。

## 发信配置缺口

当前项目没有 SMTP 或邮件服务集成。需要确定发信邮箱/服务商及其发送能力。SMTP 授权码或邮件服务 API 密钥应由用户写入服务器的私有配置文件，不放聊天、前端资源、安装包或 Git。接收验证码的恢复邮箱由用户在应用中绑定。

## 验收

覆盖首次绑定、错误/过期/重放验证码、限流、并发重设、发信失败、账号隔离、邮箱更换、已有设备未上传内容保留、密钥托管启用与备份恢复。完成后部署网页和服务端，重新打包 Android/Windows；没有安卓真机时明确保留真机验收边界。
