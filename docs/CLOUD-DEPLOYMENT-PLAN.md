# Personal Hub 公网部署方案（机主已确认）

日期：2026-10-22。目标服务器：111.91.19.235，Debian 12，2 vCPU / 2 GiB。此文件是部署计划，不是部署成功记录。

机主已确认轻量部署方案；暂无域名、先自用，手机和电脑均无旧数据。机主已放行 TCP 80/443，并明确授权使用本机 ZDB 密钥登录；已核对交接主机指纹并成功连接。不再重复请求方案批准。

## 架构与安装范围

- 使用 Caddy 提供静态网页、可信 HTTPS 与 `/v1/*` 反向代理；Node.js 24 运行现有 `server/start.ts`，SQLite 使用 Node 内置模块。无需 Docker、面板或独立数据库。
- Node 从 nodejs.org 官方发行渠道获取并校验发布校验和；Caddy 使用官方 Debian 安装来源。具体版本在实施时固定记录，不执行来历不明的一键脚本。
- 本机构建前端，仅上传部署所需的静态产物和服务端文件，不上传整个工作目录、签名文件、私钥或本机保险库数据。
- `/opt/personal-hub/releases/<版本>/` 保存发布内容，`current` 指向启用版本；`/opt/personal-hub/data/` 保存服务端 SQLite 与访问凭据；`/opt/personal-hub/backups/` 保存受限权限备份。systemd 和 Caddy 配置路径另记入部署清单。
- 服务由专用无登录用户运行，systemd 启动与故障重启，数据目录仅服务用户可访问。Node 初始内存硬上限 512 MiB、Caddy 256 MiB；上传与双端联调后评估，不把资源预算当实测用量。
- 仅对外使用 TCP 80（跳转/证书验证）和 TCP 443（网页/加密同步）；同步服务仅绑定 127.0.0.1:8787，不公开 8787 或使用旧的 3000 端口。安全组由机主决定并操作。
- 保留现有 SSH 密钥、禁用密码登录状态、fail2ban 和 Swap。新部署密钥由机主追加公钥授权。

## HTTPS 与访问控制

采用公网 IP `111.91.19.235` 的可信证书，目标地址为 `https://111.91.19.235`。2026-10-22 已核实 Let's Encrypt 正式支持 IPv4/IPv6 IP 证书，必须使用 shortlived profile，有效期 160 小时。配置自动续期和失败日志检查；上线时验证证书 SAN、信任链和 Android/Windows 实际连接。

Caddy 必须使用支持该签发方式的版本并显式配置 ACME issuer/profile，不能把旧版本对 IP 自动签发的本地 CA 证书当作公网可信证书。若所选稳定版不适配，使用官方支持的 Certbot 5.4+ webroot 方式签发，systemd 定时续期并通过 deploy hook 重新加载 Caddy；该路径仍属于同一轻量部署范围。当前仅完成文档层面的可行性核实，尚未在目标服务器签发或验证续期。

官方依据：https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability 、https://letsencrypt.org/2026/03/11/shorter-certs-certbot 。

网页和同步 API 使用同一 HTTPS 主机，客户端服务地址填写主机根地址。精确允许正式网页 Origin 和实测 Android、Windows Origin，不使用通配 CORS。访问凭据不写入前端包；首次启动在服务器生成，通过受控本地文件交付，不打印到聊天或日志。

上线前补齐并验证请求速率/并发约束、超时和容量保护；现有请求上限为 1,600,000 字节，附件为每保险库 1 GiB，记录历史与回执尚无总容量上限。不能把附件配额误认为整个数据库容量限制。限制措施应通过附件上传回归，避免正常分块同步被误限流。

## 手机与电脑同步

1. 先明确哪些设备已有数据，分别导出可恢复备份；不清空或覆盖用户现有保险库。
2. 选择已有主保险库，旧 v2 通过现有设置入口升级 v3；新账户已为 v3。
3. 使用 `.phub-device` 和独立传递的转移码将空设备加入同一保险库；两端可设置不同本机密码。如果两端已有独立数据，先制定保留及合并方案，不能直接加入覆盖。
4. 两端连接相同 HTTPS 服务与访问令牌。连接配置在各端加密保存，解锁后自动重连；前台周期拉取、修改推送与网络恢复触发同步。
5. 覆盖任务、备忘录、密码条目、资料元数据和附件的双向增删改；核验离线冲突、断网重试、锁定暂停、重启解锁恢复、附件内容一致性。

手机后台/锁屏不承诺持续即时同步。设备本地恢复信息、主密码和设备连接凭据不作为业务数据跨设备同步。现阶段共享个人账号令牌，不具有逐设备撤销能力。

## 备份、发布和验收

- 初期采用定时短暂停服备份完整数据目录，保留 serverId、凭据、SQLite 一致性；备份权限受限，设置数量与空间预算。备份成功后恢复服务，失败也必须恢复服务并记录失败。
- 同机备份只防误操作，不能应对整机丢失；异地副本目的地另行确认，不擅自把数据发送至第三方。
- 使用合成数据完成备份恢复与服务重启演练，不对真实保险库做破坏性验收。恢复旧数据库可能落后于客户端游标，不能把任意旧备份视为无条件可接续。
- 发布前运行前端生产构建、服务类型检查及 HTTP/SQLite 同步测试；服务器端再验证 HTTPS、来源控制、认证、非公开监听与资源占用。
- 用手机移动网络和电脑网络实际联调；自动测试通过不能替代真机公网验收。
- 当前工作目录含未提交桌宠开发变更，发布时明确记录所用快照及文件清单；不擅自提交或覆盖这些变更。
